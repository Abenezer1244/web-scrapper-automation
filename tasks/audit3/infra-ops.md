### Privilege review

Negative control: the code path checks both engines (`session.py:376-411`). Production `RLS_ENFORCE=true` is claimed in a comment only (not verifiable without Railway access).
- DDL: `provision_rls_roles.sql:345-356` aborts if either scoped role can `CREATE` in `public`. Neither role receives TRUNCATE, REFERENCES or TRIGGER (grants are explicit SELECT/INSERT/UPDATE[/DELETE] lists).

### Policies and the GUC
Policies bind the app role with `user_id = NULLIF(current_setting('app.current_user_id', true), '')::uuid`. The GUC is set per transaction by `get_rls_db` (API) and by `_reapply_rls_guc` (`session.py:231-240`) for `rls_sync_session`.
Reproduced locally with `SET LOCAL ROLE` on two tenants:
- app, empty GUC, `jobs`: 0 rows (fails closed).
- app, GUC = tenant A, `jobs`: 1 row (own only).
- system, empty GUC: 2 rows. system, GUC = tenant A: 2 rows. The system policies are `USING (true)` for every table (`apply_rls_cutover_policies.sql`, for example `results_system` at line 95), so the GUC has no effect for the system role. Therefore the worker's `rls_sync_session(user_id)` provides no row isolation, and worker tenant isolation relies only on the `WHERE user_id` filters (IO-7).
- app, GUC = tenant A, `users`: 2 rows readable, and an UPDATE of tenant B's `is_admin` succeeded (IO-6).
Empty GUC outcome: app role gets zero rows on every tenant table (fail-closed); only `bridgeleads_system` (and bypass roles) see everything, which matches the memory note "empty GUC = worker only as bridgeleads_system". The migration 101 triggers accept an empty GUC only for `bridgeleads_system` or bypass roles (audit #2 section 13; not re-reproduced here).

## Check 11: logs leaking secrets (including Live Run logs)

- **Live Run (job log + SSE) content.** I enumerated every `_publish_log` call with a non-literal message via AST (53 dynamic call sites in `src/workers/tasks.py`, `src/workers/tasks_helpers/enrich.py`, `status.py`). Crash paths use fixed strings (`tasks.py:386-387`, `:895`; watchdog `scheduler_helpers/health.py:343-346`). Its text can include the scraper module path, the connector `base_url`, and the raw import exception (`src/scrapers/registry.py` "Failed to load scraper class ...: {exc}"). No secrets, but internal detail (IO-15, INFO).
- **Server logs.** `install_global_redaction()` attaches the scrubber to the root logger and a few named loggers (`src/utils/logger.py:57-73`). Python applies logger-level filters only to records created on that exact logger, not to records propagated from children, and under uvicorn's logging config the root logger has no handlers. REPRODUCED: with `uvicorn.config.LOGGING_CONFIG` applied and `main` imported, records on `api.unhandled`, `security.rate_limit` and `api.readiness` were printed raw (a fake `/webhooks/tracerfy/<secret>` path, `password=`, `authorization: Bearer`), while the same text on `uvicorn.error` was redacted. Tracebacks are never scrubbed (a fake `redis://user:pass@` in an exception printed raw). The Celery worker never calls `install_global_redaction()` at all (only `main.py:164`). `api.unhandled` logs `request.url.path` (`main.py:108-109`), and the path-secret Tracerfy route is still on by default (`settings.py:345`), so an exception inside that route writes the Tracerfy secret to logs (F-22 new path, still OPEN). See IO-13.
- Negative controls that passed: modules built with `setup_logger()` (37 worker modules, most API modules) get handler-level filters, and the record is mutated before propagating, so their lines are scrubbed. `_StripTokenFilter` scrubs `token=` and the Tracerfy path on `uvicorn.access` (`main.py:114-158`). Webhook URLs are logged host-only in the live log. No logging of `Authorization` headers, cookies, DSNs or reset tokens was found in code (`grep` for `request.headers` / `.text` logging). Raw provider bodies still reach exception text: `src/scrapers/enrichment/skip_trace.py:651,657` (Tracerfy body, 500 chars) and `data_exporter.py:295,329` (R2 body, 200 chars) (E-5, carried in IO-13).
- There are still no tests for `_StripTokenFilter`, `_scrub_access_log_value` or `_RedactionFilter` (`cmd:grep -rln` in `tests/` returned nothing), which is F-27's open half.
